## 1. 新需求与旧文档的优先级

**[CONFIRMED：用户本次提出的操作目标]**

> 能不能按住左键自动挥动，取消攻击冷却，像拔刀剑一样。

将此前“可选长按连斩”的功能提案升级为需要实现的操作目标，而不是只保留一个将来可能加入的想法。
用户要的是按住后连续出刀、不必等待原版攻击蓄力条，不是只播放刀光。
“像拔刀剑一样”用于描述连续连招手感；不将某个 SlashBlade 版本的输入、动画或伤害实现冒充本项目已存在的实现。

**[PROPOSED：本轮落地解释]**

- 取消喵刀合法攻击事务中的原版攻击蓄力门槛及未满蓄力的伤害折扣。
- 保留由该武器攻速决定的连续动作间隔，而不是一帧无限次伤害。
- 普通与暗黑基础挥砍建议共用长按输入框架，但各用自己的攻速；暗黑不获得普通连击加速。
- 移除的是原版蓄力等待，不是技能冷却、重击前摇、生命体所有无敌或其他武器的规则。
- 前一版精确伤害、攻速、层数和衰减值仍为数值草案，没有因本条请求自动成为最终平衡。
- 按键重映射应跟随游戏“攻击”动作，默认是鼠标左键，不硬编码物理按钮。

如用户后续明确要求改变动作间隔或适用武器范围，应先修订本节，再重做两路线平衡，不静默将两条路线都变成每 tick 一刀。

## 2. 三种不同的时间限制

| 名称 | 本方案的处理 | 不允许的替代做法 |
| --- | --- | --- |
| 玩家原版攻击蓄力 | 仅对服务端授权的喵刀挥砍局部替换，使授权出刀不吃未充满折扣 | 全局让所有攻击强度返回 1，或只把蓄力条藏起来 |
| 喵刀动作／出刀间隔 | 保留，统一由服务端调度 | 每个渲染帧一次 hurt，或每个网络包算一刀 |
| 目标受伤冷却 | 为合法高速喵刀攻击局部适配，另有防重复命中校验 | 全局清 invulnerableTime，取消 Boss 阶段免疫 |

本次检查的 NeoForge 26.2 Player 补丁仍有 attackStrengthScale、baseDamageScaleFactor 和 fullStrengthAttack 相关分支；LivingEntity 补丁仍有受伤窗口与差值伤害逻辑。两者必须分开测试。[R1][R2]
属性面板变快、手臂挥动变快、每秒有效伤害次数变多是三件事，不能混作同一个验收结果。

## 3. 推荐的玩家操作

| 情形 | 推荐行为 [PROPOSED] |
| --- | --- |
| 按下攻击键且武器动作已就绪 | 开始一次主挥砍，不再等原版蓄力条 |
| 保持按下 | 到下一个动作时点自动挥下一刀 |
| 松开 | 立即停止本地新增请求与预测；服务端收到停止或会话超时后不再授权新刀 |
| 快速连点 | 和长按共用一个动作门闩，不比长按更快 |
| 空气中长按 | 可连续空挥；不产生伤害、不叠层、不增加战斗好感，空挥仍消耗动作时隙 |
| 准星对着方块并进入挖掘分支 | 让方块交互优先，不同时隔墙砍怪；保留原版该物品是否能挖掘的规则 |
| 对着合法实体 | 当前准星、距离、视线通过服务端校验后才结算命中 |
| 打开界面、失焦、切换物品、死亡、断线、转为器灵 | 结束当前连续攻击会话；不得出现后台一直攻击 |
| 右键正在使用物品／格挡／未来蓄力重击 | 优先执行被允许的使用动作；普通连斩暂挂或停止，具体技能取消规则另定 |

松键不回溯撤销已经被服务端提交的一刀；网络延迟下不能承诺零延迟取消远端已完成的命中。
开界面／失焦后建议要求重新按下才能开启新会话，避免返回窗口就自动砍人。
不加入自动瞄准、自动找怪、扩大攻击距离或穿墙攻击。第一版只验证准星选中的主目标；横扫沿既有规则，不因刀光很大就扩大真实伤害范围。

## 4. 与现有数值的关系

沿用 BALANCE v1 的候选表，本轮不修改任何阶段数值：

| 状态 | 设计出刀节奏 | 理想间隔 | 备注 |
| --- | ---: | ---: | --- |
| 普通九阶，0 层 | 5.0 次/秒 | 0.200 秒 | 已经具备连续斩击基础速度 |
| 普通九阶，20 层 | 6.0 次/秒 | 约 0.167 秒 | 每层基础攻速 +1%，满层合计 +20% |
| 暗黑八阶，基础挥砍 | 1.6 次/秒 | 0.625 秒 | 无普通连击加速，不等于每刀重击 |

基准为稳定 20 TPS、没有外部增益。表中“次”是主动作授权次数，真实命中还受目标、护盾和伤害管线影响。
普通每层增伤 +3%、加速 +1%、有效命中最多加一层、用旧层数计算当前一刀的规则不变。
空挥可有动作，但不能给 comboStacks 或 affection 加值。

## 5. 客户端输入与服务端职责

### 5.1 客户端 [PROPOSED]

客户端负责读取当前攻击动作是否按住，以及本地界面／焦点／物品使用状态。
监听持续按下状态，不只消费单次点击边沿；也不要在 render frame 中循环发送命中。
按键输入属于客户端，网络消息将意图传给服务端；不得引用客户端类到独立服务器公共入口。[R3][R4]

可以采用开始／更新／停止的输入会话：

```text
AttackIntent
  sessionEpoch
  sequence
  held
  slotHint
  weaponIdentityHint
  targetHint (optional)
```

这是建议协议，不是本项目已注册的数据包。不得包含客户端决定的伤害、层数增量或实际攻速。
需要心跳与超时保护，以便松键消息没有及时处理、切屏或连接停止时服务端能够停止。
心跳周期和超时数值是网络原型参数，不是用户已定玩法；先做丢包／延迟测试再固定。

### 5.2 服务端 [PROPOSED]

服务端保存玩家当前会话、上次输入序号、活动武器身份和动作进度。
每个服务器 tick 只推进一次状态，不按收到多少包推进多少次。
重复或过期序号不重复出刀；每次授权时重新检查玩家存活、主手、路线上限、模式、物品使用、控制状态和输入是否过期。
不能仅凭客户端提供的 targetId 接受命中；服务端必须验证范围、视线和目标合法性。
未知或未授权的自定义攻击请求安全拒绝，不降级成“客户端说多少伤害就是多少”。

所有被接管的普通左键攻击都只能通过一个主流程结算。
原版单击路径与自定义长按路径不得同时执行，使首刀变成两份伤害。
同一事务编号只允许一次主伤害、一次对应耐久结算和一次连击更新；伤害被取消时不凭刀光给奖励。

## 6. 连斩节奏器 [PROPOSED]

### 6.1 保留小数进度

使用服务器 tick 时间与独立的动作进度，按当前攻速推进。
不要把 20 / 6 向上取整并固定为 4 tick，那会把 6 次/秒退回 5 次/秒。
采用带余量的进度模型，稳定六次/秒时可以出现 4、3、3 tick 或等价相位的间隔序列；长期平均维持 6，而不是承诺每一刀严格 0.167 秒。

概念算法：

```text
每个新的服务器 tick：
    根据服务端当前有效攻速推进动作进度
    若有有效持续输入且动作进度达到 1：
        授权至多一个主挥砍
        减去 1，保留正常的小数余量
    若输入无效或没有在执行挥砍：
        就绪额度最多保留一刀，不攒多刀
```

重要：在有效持续攻击时，不能先把所有超过 1 的进度裁成 1 再减去 1，否则会丢失小数余量，仍然变成假加速。
原型允许首次完全就绪时及时出刀；按下、松开、重复 START、切换会话不重置动作进度为就绪。
切换物品／器灵交接不能绕过尚未结束的动作约束；复杂的跨武器动作取消是后续规则，不赠送无限首刀。

### 6.2 停止与服务器变慢

只处理当前有效动作机会，不循环追赶大量历史 nextAttackTime。
卡顿恢复不能同一 tick 对目标补发若干刀；每玩家每 tick 至多一个主动作。
断流期间不积攒攻击，空挥期间消耗动作时隙，换目标后不能一口气把空气中积攒的“刀数”打出去。
动作基于游戏时间。20 TPS 下的 6 次/秒设计不能在 10 TPS 服务端靠墙钟补成每秒 6 刀；测试必须同时记录 tick 和墙钟。
过高外部攻速的限幅／溢出策略需显式配置和日志，不暗中覆盖其他 Mod 的属性。

### 6.3 松键与层数不是一回事

松键停止新增挥砍，不等于立刻清空连击。连击仍按 BALANCE 的宽限和衰减候选规则处理。
切到其他武器、死亡、断线或器灵转换则按候选规则清短期加成；好感度不清零。

### 6.4 合并旧 COMBAT_INPUT 的补充约束

- 每次授权建立不可混淆的 `attackId` / 主攻击上下文，快照本刀所用武器、阶段与连击层数。
- 临时攻速只应用一次：若节奏器读取的是已经包含连击修饰的属性，就不得再乘一次连击倍率。
- 旧会话 Stop/Start、切槽、器灵收放不能重新发放免费首刀。主手已有其他物品时不能覆盖。
- 客户端预测与服务端确认的同一攻击表现须去重；服务端伤害和奖励不以预测为准。
- 即使局部适配受伤冷却，也不能无条件恢复旧 lastHurt/时间，从而覆盖嵌套伤害或反伤产生的合法状态变化。
- 右键物品使用与正在挖掘时保留互斥规则；长按不自动触发器灵召回或暗黑重击。

## 7. 取消原版攻击蓄力的安全边界 [PROPOSED]

对当前合法的 AbsMod 主攻击建立作用域明确的攻击上下文，局部替换原版蓄力门槛和蓄力伤害折扣。
不永久修改玩家基础属性，不全局令所有 getAttackStrengthScale 返回满值，不通过极大 attack_speed 伪装无冷却。
仅删除蓄力条 UI 不算实现。即使本次动作在整数 tick 上早于旧充能判定，授权一刀也应按设计的该刀威力结算。

需要在当前 26.2 映射源码确认并分别处理：

1. 客户端发起攻击入口以及任何提前的原版 delay/minimum-charge 判断。
2. 服务端对应的攻击准入与攻击强度读取。
3. 基础伤害与附魔增量的蓄力缩放。
4. 暴击、冲刺击退、横扫所依赖的满强度条件。保留其余条件，不把所有自动攻击直接标成暴击。
5. 原版攻击冷却 HUD，仅在接管的喵刀上下文替换／隐藏，不修改其他物品。
6. 物品技能冷却、眩晕和其他动作限制，不能因“无原版蓄力”一并删除。

只有 `MeowBladeItem` 的 instanceof 判断还不足以覆盖未来暗黑类，应该通过共同接口／标签／稳定类型入口识别可接管武器。
Mixin 是可能使用的局部适配工具，不预设具体方法签名或注入点已可编译。优先核对现有 API 和源代码，两个加载器分别验证。

## 8. 目标受伤窗口与战斗兼容 [PROPOSED]

合法高速主攻击要能命中同一个高血量目标，但不能破坏其他来源伤害的时序。
候选是喵刀专属伤害上下文／伤害类型配合局部 hook，而不是所有玩家攻击都绕过冷却。
仅增加 `bypasses_cooldown` 标签也不自动证明兼容：仍要检查共享 lastHurt 和 invulnerableTime 是否被本次高速伤害污染，以及之后箭矢／燃烧／另一玩家伤害是否异常被拒绝。

必须保留：护甲、韧性、护盾／格挡、抗性、攻击取消事件、友伤设置、创造／旁观保护、Boss 阶段免疫、伤害来源归属、死亡和附魔后处理。
不通过直接 setHealth 扣血绕过上述流程；不为了补偿漏伤在同一事务再调用一次伤害函数。
纯受伤冷却适配与瞬间无敌／完全免疫不是同一件事。

- 当前刀光不负责主攻击调度、不自动造成额外伤害；MeowBladeItem 的攻速构造仍是 -2.4。
- README 记录每道刀光 18 tick、最多 32 道、32 格内；这些是现有实现参数，不是本轮新批准的美术目标。[R5][R6]

**[PROPOSED]** 先复用现有轨迹和着色，不另写第二套重叠刀光。
在高速动作下验证原版 swing 布尔值是否足以区分每一刀；必要时由服务器接受的主动作编号驱动视觉播放。
切换到动作编号后，对该武器停用旧 swing 监听的重复触发，不能每刀同时发“新协议刀光＋旧监听刀光”。
视觉连招序号与增伤 comboStacks 分开。现有六种轨迹循环不是只有六层 Buff。
长按对空气可以播放动作效果，但不得算命中；挖掘产生的已有装饰效果可保留为纯视觉，不允许参与主攻击层数。
远程玩家加入跟踪时取得必要的序号／动作状态，避免把客户端本地序列误当权威伤害顺序。
持续高速下测试帧率、光带重叠、遮挡和声音叠加；没有用户确认不擅自删改现有已选刀光风格。

## 10. 器灵和暗黑重击保持独立

“剑已经在主手时长按连斩”已经有明确目标；“猫娘何时自动飞回手中”仍未选定触发规则。
不因本条需求默认看到敌人就抢主手、受伤就强制变剑或长按时永久禁止显现。
召回必须先由 SpiritTransformationService 安全交付剑，之后才允许这把剑的首击，不能空手结算完再替换物品。
暗黑可评估相同长按普通挥砍入口，但低速与高单击保持。长按不默认等于蓄力重击，不会每一刀都眩晕。
重击输入、倍率、独立冷却、眩晕秒数、对 Boss/PvP 规则均仍为 TBD。

## 11. 分批任务与验收

| 任务 | 内容 | 成功标准 |
| --- | --- | --- |
| AUTO-01 | 输入状态、序号、会话开始／停止和超时 | 长按持续、松键停止、失焦不后台攻击、按键重映射有效 |

| AUTO-05 | 接入现有刀光与声音 | 每次动作只触发一组效果，空挥不刷 Buff，挖掘不造成主攻击 |
| AUTO-06 | 双加载器单人与多人回归 | 发布前逐场景验收，不能仅凭动画／公式通过标 DONE |

最低游戏测试矩阵：

- 一阶与九阶，冷启动、持续命中、空气、多个目标之间切换、完全格挡。
- 单击与快速连点都不快于长按，重复 START/过期序号不再给首刀。
- 长按中松键、打开背包/聊天、切屏、换手、掉落武器、武器损坏、断线、死亡。
- 右键使用与未来重击不冲突；方块优先时不穿墙攻击。
- 稳定 20 TPS：普通九阶满层，连续 200 tick 在无限制测试目标上约 60 个主命中；记录窗口端点规则。
- 记录实际血量/吸收变化而非刀光数；暴击和附魔另测，不混入基础表。
- 低 TPS、高延迟、输入心跳过期、恢复后无补刀爆发。
- 多玩家、箭矢、燃烧、反伤和 Boss 免疫；外部取消事件有效。
- 两加载器编译、独立服务器启动、客户端视觉和不同 FPS 下节奏分别验证。
- 现有 18 tick 刀光在 6 次/秒下的遮挡和资源成本，不把几何测试通过等价 GPU 验收通过。
