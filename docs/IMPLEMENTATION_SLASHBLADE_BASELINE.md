## Implemented boundaries

- Data: `assets/absmod/animations/slashblade_baseline.json`, generated by `tools/animation/import_slashblade_baseline.py`. Individual clips and their recovery can be replaced without changing server combat.
- Sampling: `BladeMotionPreset`; 60 Hz source samples, quaternion interpolation, explicit strike/recovery, blended joins for cropped recovery. Strike duration is 85% of the authorized interval with a 1.5–6 tick presentation bound; recovery uses source timing, not whole-animation speedup.
- Playback: `BladeMotionPlayer`; UUID-keyed latest state, attackId deduplication, sequence rejection, server game-time start, no queue. Each render snapshot owns its pose values. Reload clears active playback and reloads the preset; errors explicitly disable custom motion.
- First person: `BladeFirstPersonMixin` and `BladeGrip`; original item art rendered once with sampled position/rotation, calibrated diagonal-sprite handle offset and thin edge depth. Recovery blends into a custom resting grip. Original normal-item and block-mining paths remain available. No sheath or replacement nine-stage PNG.
- Third person: `BladePoseExtractionMixin`, `BladePoseStateMixin`, `BladePlayerPoseMixin`, `BladeThirdPerson`; 26.2 avatar render-state snapshot, torso/arm pose, left-hand reflection, arm shoulder pivots carried with torso rotation. Vanilla skin, leg movement and original held-item layer remain. The weapon follows the posed hand; this is not a second independent copy of the upstream sheath/weapon layer.
- Effects: `MeowSlashEffects.confirm` starts the same accepted preset action and uses its effect plane. It no longer resets vanilla `swingTime`. Legacy observation remains outside the authorized main-hand path. No damage code in the animation subsystem.
- Protocol: shared `BladeSwingPayload` adds sequence, server start tick and interval. NeoForge registrar version is 2; both sides must use this build. Fabric also requires matching payload layout; mixed old/new clients are not supported.
- Server: `BladeCombatServer` adds presentation fields at its existing confirmation send point. Its cadence, attack executor, hit counting and combo state were not changed by this task.

Client-only mixins stay in the client list; no common server entrypoint imports animation classes. Both loader modules use the shared implementation; no legacy playerAnimator dependency is installed.
